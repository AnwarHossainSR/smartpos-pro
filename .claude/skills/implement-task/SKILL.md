# Implement a roadmap task

You implement exactly **one** task from `docs/REQUIREMENTS.md`, end to end.

## 1. Resolve the task
- Read the task id from the arguments (accept `43`, `T43`, "task 43").
- Open `docs/REQUIREMENTS.md`, find that `T<id>` entry, and read its **Scope** and
  **Done when**. If the id doesn't exist, list the nearest task ids and stop.
- Open `docs/PROGRESS.md`. If the task is already ✅, tell the user and ask whether to
  redo it before proceeding.
- Read `CLAUDE.md` and `docs/ARCHITECTURE.md` so your implementation matches conventions.

## 2. Prepare the branch
- Dev branch is `claude/new-github-repo-setup-tb3viy`.
- If its open PR was already merged, restart it from main:
  `git fetch origin main && git checkout -B claude/new-github-repo-setup-tb3viy origin/main`.
  Otherwise just continue on it (`git checkout claude/new-github-repo-setup-tb3viy`).

## 3. Implement (follow CLAUDE.md)
- **Backend task** (`api`): add migration → model (with `BelongsToTenant`) → FormRequest
  → Service (domain logic in a transaction; stock via `StockLedgerService`, money via
  `JournalService`) → Controller (thin) → API Resource → versioned route guarded by
  `permission:<module>.<action>` (add new slugs to `PermissionCatalog`). Write a feature
  test under `tests/Feature/Api` using `Tests\Support\CreatesTenants`.
- **Frontend task** (`web`): add the page/route under `src/app`, components under
  `src/components`, data hooks over `src/lib/api.ts` + TanStack Query. Handle
  loading/empty/error states and permission checks. Keep to the design tokens.
- Do only what the task's Scope covers. If you discover necessary follow-ups, add them as
  new `T<n>` rows rather than expanding this task.

## 4. Verify
- Backend: `php artisan test` and `vendor/bin/pint` (must pass/clean).
- Frontend: `cd web && npm run lint && npm run build` (must succeed).
- If checks fail, fix before continuing — never mark a task done on red.

## 5. Record & ship
- In `docs/PROGRESS.md`: flip the task's status to ✅ (or 🚧 if genuinely partial), set the
  PR column, and update the phase counts + totals in the Summary table and the
  _Last updated_ date.
- For backend endpoints, add them to `docs/API.md`.
- Commit with a message starting `T<id>: <short title>` and the standard co-author footer.
- Push the dev branch (`git push -u origin claude/new-github-repo-setup-tb3viy`). Open a PR
  to `main` if none is open, else the push updates the existing PR. End the PR body with
  `_Generated by [Claude Code](https://claude.ai/code)_`.

## 6. Report
Tell the user: what was built (files/endpoints/screens), test/build result, the PROGRESS
row now ✅, and the PR link.
