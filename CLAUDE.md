# SmartPOS Pro — Conventions for Claude

A multi-tenant POS & retail SaaS. **Backend**: Laravel 13 / PHP 8.4 at the repo root.
**Frontend**: Next.js 16 / React 19 in [`web/`](web). Product spec:
[`docs/PROJECT_SPEC.md`](docs/PROJECT_SPEC.md). Deeper design:
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Task-driven workflow

- Work is broken into numbered tasks in [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md);
  live status in [`docs/PROGRESS.md`](docs/PROGRESS.md).
- Run **`/implement-task <id>`** to implement one task, or **`/project-status`** to see
  what's left.
- **Dev branch:** `claude/new-github-repo-setup-tb3viy`. Never push to `main`; open a PR.

## Backend conventions (root)

- **Tenancy is non-negotiable.** Every business-owned model uses the
  `App\Support\Concerns\BelongsToTenant` trait (auto-scopes reads, auto-fills `tenant_id`).
  Never write a raw cross-tenant query outside `withoutTenancy()`.
- **Layering:** `Controller` → `FormRequest` (validation) → `Service` (domain logic) →
  `Model`; shape responses with an API `Resource`. Keep controllers thin.
- **Money & stock move through services, never controllers.** Stock changes go through
  `StockLedgerService` inside a DB transaction; accounting through `JournalService`.
- **Routes:** versioned under `routes/api.php` `/v1`, guarded with
  `permission:<module>.<action>` (see `PermissionCatalog`). Add new permission slugs there.
- **Tests are required.** Add a feature test under `tests/Feature/Api` using the
  `Tests\Support\CreatesTenants` helper. Run `php artisan test` + `vendor/bin/pint`.
- New permission modules must be added to `App\Support\Rbac\PermissionCatalog`.

### Backend definition of done
`php artisan test` green · `vendor/bin/pint --test` clean · new endpoints documented in
`docs/API.md` · `docs/PROGRESS.md` updated.

## Frontend conventions (`web/`)

- App Router, TypeScript strict, Tailwind v4 tokens in `src/app/globals.css`.
- API calls go through `src/lib/api.ts`; auth token via `src/stores/auth.ts`; server state
  via TanStack Query. UI primitives live in `src/components/ui`.
- Every list = search + filter + pagination + empty + loading (skeleton) states.
  Every mutation = validation + confirm-on-destructive + toast.
- Guard app routes; check permissions with `useAuth().can('module.action')`.

### Frontend definition of done
`npm run lint` clean · `npm run build` succeeds · states (loading/empty/error) handled.
